# Farmer Credit Assessment System

A Flask and machine-learning web application for agricultural credit-risk assessment. The system combines crop yield, production, rainfall, fertilizer, drought, soil, and global food-price indicators to estimate a farmer's credit-risk level and preserve prediction history for user and admin review.

## Deployment

Render Blueprint deployment is configured through `render.yaml`.

## Features

- User signup, login, logout, and role-based dashboard routing with Flask-Login.
- PostgreSQL-backed user accounts and prediction history.
- Farmer credit-risk prediction API powered by a trained ML model.
- Five risk categories: Very Low, Low, Medium, High, and Very High Risk.
- Confidence score and probability output for every prediction.
- Assessment history for farmers and complete assessment history for admins.
- CSV export for individual and admin-level assessment records.
- Admin-only model training page with server-sent training logs.
- HTML training reports generated by the training pipeline.
- Contact form email delivery through Gmail SMTP configuration.
- Render Blueprint for production deployment with a managed PostgreSQL database.

## Environment Variables

Create `.env` from `.env.sample`.

```env
PG_HOST=localhost
PG_PORT=5432
PG_USER=postgres
PG_PASS=<postgres-password>
PG_DB=farmer_credit
SECRET_KEY=<flask-secret-key>
GMAIL_USER=<smtp-user>
GMAIL_PASS=<smtp-app-password>
CONTACT_RECEIVER=<contact-recipient-email>
```

Required for the core app:

- `PG_HOST`
- `PG_PORT`
- `PG_USER`
- `PG_PASS`
- `PG_DB`
- `SECRET_KEY`

Optional for contact form email:

- `GMAIL_USER`
- `GMAIL_PASS`
- `CONTACT_RECEIVER`

Render can also use a standard `DATABASE_URL`; the app supports both `DATABASE_URL` and the separate `PG_*` variables.

## Run Locally

Create and activate a virtual environment:

```bash
python -m venv .venv
.venv\Scripts\activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Create `.env`:

```bash
copy .env.sample .env
```

Create a PostgreSQL database named `farmer_credit`, then start the app:

```bash
python app.py
```

Open:

```text
http://localhost:5000
```

The app creates the `users` and `predictions` tables automatically on startup.

## Model Training

The training pipeline loads the local `Dataset/` folder, engineers agricultural and climate features, trains multiple classifiers, chooses the best model, writes a timestamped model package, and updates `Trained_models/latest_model.pkl`.

Run training manually:

```bash
python train_model.py
```

The training pipeline generates:

- `training_report.html`
- `Trained_models/model_<timestamp>/farmer_credit_model_<timestamp>.pkl`
- `Trained_models/latest_model.pkl`

Admin users can also open `/train-model` in the web app to stream training logs.

## API Endpoints

| Method | Route | Access | Description |
| --- | --- | --- | --- |
| `POST` | `/api/predict` | Logged-in user | Generate a farmer credit-risk prediction |
| `GET` | `/api/test-model` | Public | Verify that the ML model loads and predicts |
| `GET` | `/api/debug-auth` | Public | Debug current authentication state |
| `GET` | `/api/expert/<pred_id>` | Logged-in user | Return feature importance, sensitivity, and recommendations |
| `GET` | `/download-history` | Logged-in user | Download current user's prediction history |
| `GET` | `/download-history-all` | Admin | Download all users' prediction history |

## Render Deployment

This repo includes `render.yaml` for Render Blueprint deployment.

1. Push the repository to GitHub.
2. Open Render and choose **New > Blueprint**.
3. Select the GitHub repository.
4. Render creates:
   - a Flask web service
   - a free PostgreSQL database
   - linked `PG_*` environment variables
5. Deploy the service.

Render settings:

```text
Build command: pip install -r requirements.txt
Start command: gunicorn app:app
```

The web service uses `Trained_models/latest_model.pkl` for inference. Raw datasets are not required for prediction, only for retraining.

## Default Workflow

1. Sign up as a user.
2. Log in.
3. Open the predictor.
4. Submit agricultural, climate, soil, and market indicators.
5. Review the risk level and confidence score.
6. Download assessment history as CSV when needed.

Admin users can access assessment history across all users and run model training.
